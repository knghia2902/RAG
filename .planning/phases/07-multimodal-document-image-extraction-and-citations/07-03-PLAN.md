# Plan 07-03: Multimodal RAG Retrieval & Gemini Vision Generation

<threat_model>
## Security Threat Model (ASVS L1)

| Threat ID | Category | Threat Description | Mitigation Strategy |
|-----------|----------|-------------------|---------------------|
| T-07-04 | Context Overflow & Prompt Injection via Image | Ảnh độc hại hoặc gửi quá nhiều ảnh vượt quá context window gây sập request hoặc timeout | Bounded image limit: Giới hạn tối đa 2-3 ảnh liên quan nhất được gửi kèm prompt; resize ảnh trước khi encode base64 |
| T-07-05 | Cross-Dataset Image Leakage in LLM Prompt | Prompt gửi ảnh thuộc dataset mà người dùng không có quyền truy cập | RAG retrieval lọc `dataset_id` từ trước bằng ACL mask; chỉ các ảnh thuộc chunk hợp lệ và đang active mới được đưa vào danh sách ảnh gửi cho LLM |
</threat_model>

<context>
Theo các quyết định D-03, D-04, D-11:
- **D-03 (Gemini Multimodal Vision Integration):** Tận dụng khả năng Multimodal Vision của Google Gemini (`gemini-flash-lite-latest`). Khi RAG truy xuất được các đoạn văn bản (chunks) có hình ảnh liên quan, hệ thống gửi kèm trực tiếp hình ảnh (base64 inline part, giới hạn top 2-3 ảnh) cùng với prompt vào API.
- **D-04 (Vision-Guided Grounded Citations):** Gemini đối chiếu trực tiếp chi tiết trong ảnh (sơ đồ khối, sơ đồ mạng, bảng thông số, trạng thái cấu hình trên màn hình chụp) để trả lời và sinh thẻ trích dẫn ảnh rõ ràng (`![Mô tả ảnh](/api/v1/datasets/.../images/{image_id})`).
- **D-11 (Relevance Scoring):** Lọc và sắp xếp độ liên quan giữa câu hỏi và các hình ảnh trích xuất của chunk để chọn top 2-3 ảnh tối ưu nhất.
</context>

### Task 07-03-02: Gemini Multimodal Vision Prompt Construction
<read_first>
- `backend/app/providers/openai_llm.py`
- `backend/app/config.py`
</read_first>
<action>
Mở `backend/app/providers/openai_llm.py`:
- Mở rộng phương thức `generate_answer` / `generate_grounded_answer`:
  - Thêm tham số `images: list[dict] | None = None` (mỗi dict chứa `image_id`, `base64_data` hoặc `storage_path`, `mime_type`, `api_url`).
  - Nếu `images` có dữ liệu:
    - Đọc file ảnh từ đĩa (nếu truyền đường dẫn), mã hóa base64 chuẩn: `b64 = base64.b64encode(img_bytes).decode('utf-8')`.
    - Tạo `user_content` dạng danh sách các phần tử theo chuẩn OpenAI/Gemini Multimodal:
      ```python
      content = [{"type": "text", "text": prompt_text}]
      for img in images[:3]: # Giới hạn tối đa 3 ảnh
          content.append({
              "type": "image_url",
              "image_url": {
                  "url": f"data:{img['mime_type']};base64,{img['b64']}"
              }
          })
      ```
    - System prompt bổ sung hướng dẫn:
      `"Nếu trong ngữ cảnh có hình ảnh hoặc sơ đồ kỹ thuật, hãy quan sát kỹ các thông số/chi tiết trong hình ảnh để trả lời chính xác và chèn trích dẫn ảnh bằng cú pháp Markdown: ![Mô tả ảnh](IMAGE_API_URL)."`
  - Gửi request tới Gemini qua client và xử lý kết quả trả về như thông thường.
</action>
<acceptance_criteria>
- `backend/app/providers/openai_llm.py` hỗ trợ tạo và gửi payload multimodal `image_url` dạng base64.
- Giới hạn cứng tối đa 3 ảnh/request để bảo vệ latency và token.
</acceptance_criteria>
