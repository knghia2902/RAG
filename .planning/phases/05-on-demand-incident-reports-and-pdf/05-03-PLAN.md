# Plan 05-03: Report Persistence, Database Migration & FastAPI API Routes

<threat_model>
## Security Threat Model (ASVS L1)

| Threat ID | Category | Threat Description | Mitigation Strategy |
|-----------|----------|-------------------|---------------------|
| T-05-05 | IDOR (Insecure Direct Object Reference) | Kỹ thuật viên truy cập hoặc tải báo cáo của kỹ thuật viên khác nằm ngoài phạm vi phân quyền | Endpoint `GET /{id}` và `GET /{id}/pdf` chỉ cho phép Admin xem mọi báo cáo; Kỹ thuật viên chỉ được xem báo cáo do chính mình tạo và nằm trong các dataset được cấp quyền |
| T-05-06 | Stale Permission / Scope Violation | Tài khoản đã tạo báo cáo nhưng sau đó bị Admin thu hồi quyền truy cập vào dataset nguồn | Thực thi cơ chế Live Scope Recheck (AUTH-04, REP-06): Đối chiếu `report.dataset_ids` với `allowed_dataset_ids` hiện hành của tài khoản; nếu có bất kỳ dataset nào bị thu hồi quyền, từ chối ngay với HTTP 403 Forbidden |
</threat_model>

<context>
Theo yêu cầu REP-05, REP-06, AUTH-04, SYS-05 và quyết định D-04, D-05:
- Tạo bảng `reports` lưu trữ báo cáo với đầy đủ snapshot số liệu KPI, `dataset_ids` tham chiếu, nhận định LLM và danh sách tệp nguồn.
- Tạo migration Alembic `0005_incident_reports.py`, đồng thời cập nhật whitelist trong `backend/app/api/health.py` và `test_migrations.py` để đảm bảo Docker healthcheck luôn đạt trạng thái healthy.
- LLM chỉ sinh các đoạn văn bản nhận định xu hướng và khuyến nghị theo SOP (không can thiệp số liệu). Khi LLM gặp sự cố hoặc timeout, hệ thống vẫn xuất báo cáo đầy đủ kèm thông báo cảnh báo rõ ràng (SYS-05).
- Cung cấp các endpoint tại `/api/v1/reports`: `POST /generate`, `GET /history`, `GET /{id}`, `GET /{id}/pdf`, `GET /{id}/provenance`.
</context>

### Task 05-03-01: Schema Migration & Persistence for Reports Table
<read_first>
- `backend/app/database/models.py`
- `backend/alembic/versions/0004_incident_analysis.py`
- `backend/app/api/health.py`
</read_first>
<action>
1. Cập nhật `backend/app/database/models.py`:
   - Thêm model `Report`:
     - `id`: UUID primary key
     - `account_id`: ForeignKey("accounts.id"), index=True
     - `title`: String(255)
     - `period_type`: String(32) ('daily', 'weekly', 'monthly', 'custom')
     - `start_time`: DateTime(timezone=True)
     - `end_time`: DateTime(timezone=True)
     - `dataset_ids`: JSONB (danh sách UUID string)
     - `metrics_json`: JSONB
     - `narrative_json`: JSONB
     - `provenance_json`: JSONB
     - `created_at`: DateTime(timezone=True), default=utcnow

   - Bổ sung `"0005_incident_reports"` vào danh sách phiên bản migration hợp lệ trong hàm `database_ready()`.
4. Cập nhật `backend/tests/integration/test_migrations.py`:
   - Bổ sung `"0005_incident_reports"` vào các assert `alembic_version`.
</action>

### Task 05-03-02: Guarded Narrative Synthesizer & Report Service Layer
<read_first>
- `backend/app/modules/reports/contracts.py`
- `backend/app/modules/reports/aggregator.py`
- `backend/app/llm/provider.py`
- `backend/app/rag/secret_filter.py`
</read_first>
<action>
1. Tạo `backend/app/modules/reports/narrative.py`:
   - Lớp `ReportNarrativeSynthesizer`:
     - Nhận `ReportMetricsDTO` và tóm tắt sự cố trong kỳ.
     - Áp dụng `mask_secrets` trên prompt trước khi gửi đến LLM Provider.
     - Yêu cầu LLM sinh JSON gồm: `executive_summary`, `root_cause_analysis`, `recommendations` (trích dẫn SOP liên quan), và `missing_data_warnings`.
     - Tích hợp bộ tổng hợp tất định dự phòng (deterministic fallback) khi LLM timeout hoặc gặp lỗi: sinh văn bản tóm tắt dựa trên số liệu KPI có sẵn và gắn nhãn thông báo (SYS-05).
2. Cập nhật `backend/app/modules/reports/service.py`:
   - Lớp `ReportService`:
     - `generate_report(db, account_id, filter_dto, allowed_dataset_ids) -> Report`:
       - Kiểm tra các `dataset_ids` yêu cầu có nằm trong `allowed_dataset_ids` hay không (nếu không, ném 403 Forbidden).
       - Tính toán mốc biên thời gian qua `compute_period_bounds`.
       - Truy vấn các `incident_analyses` và `canonical_records` trong phạm vi kỳ và dataset.
       - Tính toán số liệu tất định qua `aggregate_report_metrics`.
       - Thu thập snapshot `provenance_sources` (source ID, version number, filename).
       - Gọi `ReportNarrativeSynthesizer` sinh nhận định.
       - Lưu bản ghi vào bảng `reports` và trả về entity.
     - `get_report_detail(db, report_id, account, allowed_dataset_ids) -> ReportDetailDTO`:
       - Kiểm tra quyền sở hữu IDOR (Admin hoặc chính chủ).
       - Thực thi Live Scope Recheck: kiểm tra `report.dataset_ids` có nằm trọn vẹn trong `allowed_dataset_ids` hiện hành không. Nếu bị thu hồi quyền đối với bất kỳ dataset nào, ném 403 Forbidden.
     - `get_report_pdf(db, report_id, account, allowed_dataset_ids) -> tuple[bytes, str]`:
       - Thực hiện Live Scope Recheck tương tự `get_report_detail`.
       - Gọi `ReportPDFGenerator.generate_pdf` và trả về `(pdf_bytes, filename)`.
</action>
<acceptance_criteria>
- `backend/app/modules/reports/narrative.py` và `service.py` xử lý hoàn chỉnh luồng tạo báo cáo, fallback narrative, và Live Scope Recheck.
- Nếu LLM Provider ném ngoại lệ hoặc timeout, hàm `generate_report` vẫn hoàn thành thành công và điền fallback narrative kèm cờ cảnh báo SYS-05.
</acceptance_criteria>
