### Threat Assessment (ASVS L1)
- **T-03-06 (Cross-Tenant / Cross-Dataset Leakage):** Truy vấn vector tìm kiếm tương đồng trên toàn bảng có thể trả về các chunk thuộc dataset mà người dùng không có quyền.
  - *Mitigation:* Luôn thêm điều kiện `WHERE embedding_records.dataset_id IN (:allowed_ids)` trực tiếp trong câu query SQL trước khi tính cosine distance hoặc top-k limit.
- **T-03-07 (Lexical Identifier Confusion / Collisions):** Mã đơn `DH001` bị tìm kiếm dưới dạng substring lỏng lẻo dẫn đến ghép nhầm đơn `DH0010` hoặc `DH0011`.
  - *Mitigation:* Sử dụng boundary regex `\mDH001\M` (PostgreSQL word boundary) hoặc đối sánh chính xác trường `record_metadata->>'order_id' = 'DH001'`.
</threat_model>

<name>03-03-02: Dense Pgvector Cosine Search & Hybrid Rank Fusion</name>
<files>backend/app/rag/retrieval.py, backend/tests/integration/test_hybrid_retrieval.py</files>
<read_first>backend/app/database/models.py, backend/app/rag/contracts.py, backend/app/rag/lexical.py, backend/app/providers/fake.py</read_first>
<action>
1. Tạo `backend/app/rag/retrieval.py`:
   - Class `HybridRetriever`:
     - Khởi tạo với `EmbeddingProvider` và `LexicalMatcher`.
     - Method `retrieve(db: Session, request: RetrievalRequest, scope: AuthorizedScope, top_k: int = 5, profile_id: str | None = None, start_time: datetime | None = None, end_time: datetime | None = None) -> list[EvidenceChunk]`:
       1. Trích xuất mã định danh qua `lexical_matcher.extract_identifiers(request.query)`.
       2. Nếu có mã định danh: chạy `lexical_matcher.search_exact_identifiers` trong phạm vi `scope.dataset_ids`. Các kết quả này được đánh dấu hạng ưu tiên cao nhất (`rank = 1.0`).
       3. Sinh vector nhúng cho câu hỏi qua `embedding_provider.embed_texts([request.query])[0]`.
       4. Truy vấn dense cosine similarity trên `embedding_records`:
          - Câu lệnh SQLAlchemy:
            ```python
            stmt = (
                select(CanonicalRecord, EmbeddingRecord.embedding.cosine_distance(query_vector).label("distance"))
                .join(EmbeddingRecord, EmbeddingRecord.canonical_record_id == CanonicalRecord.id)
                .join(SourceVersion, CanonicalRecord.source_version_id == SourceVersion.id)
                .join(Source, SourceVersion.source_id == Source.id)
                .where(
                    EmbeddingRecord.dataset_id.in_(scope.dataset_ids),
                    Source.deleted_at.is_(None),
                    Source.active_version_id == SourceVersion.id,
                )
            )
            ```
          - Áp dụng các bộ lọc bổ sung nếu có (profile_id, start_time, end_time).
          - `order_by("distance").limit(top_k * 2)`.
       5. Hợp nhất kết quả (Hybrid Fusion):
          - Đặt các kết quả lexical match chính xác lên đầu tiên (boosted).
          - Điền tiếp các kết quả dense vector có khoảng cách nhỏ nhất, loại trừ các bản ghi trùng lặp (`canonical_record.id`).
          - Giới hạn đúng `top_k` kết quả tốt nhất.
       6. Chuyển đổi thành danh sách `EvidenceChunk`:
          - `dataset_id`: `record.dataset_id`
          - `locator`: ánh xạ từ `record.locator_data` thành `SourceLocator` đầy đủ (page, line, sheet, row, json_path).
          - `text`: `record.content_text`
          - `metadata`: `{"source_id": str(source.id), "logical_filename": source.logical_filename, "version": source_version.version_number, ...}`
2. Mở rộng test trong `backend/tests/integration/test_hybrid_retrieval.py`:
   - Kiểm tra câu hỏi chung (không có order ID): tìm kiếm dense trả về các đoạn liên quan ngữ nghĩa.
   - Kiểm tra câu hỏi kết hợp cả order ID và ngữ nghĩa (ví dụ: `"Sự cố tồn kho của đơn DH001"`): trả về đúng bản ghi của DH001 và đoạn SOP tồn kho liên quan.
</action>
